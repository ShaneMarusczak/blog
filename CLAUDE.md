# CLAUDE.md

A static blog for GitHub Pages, generated by a tiny Python script. No
frameworks, and **no runtime JavaScript** — every page is plain static HTML
by the time it ships.

## How the site is built

`tools/build.py` stamps shared templates around per-post content to produce
the finished pages. You edit the sources; the script writes the output.

```
SOURCES (edit these)                 GENERATED (never hand-edit; commit them)
--------------------                 ----------------------------------------
posts.json          ─┐
content/posts/*.html ─┼─ build.py ─▶ index.html
templates/*.html     │               posts/*.html
partials/*.html     ─┘               feed.xml, sitemap.xml, robots.txt
```

- `posts.json` — the front matter for every post: `file`, `title`, `date`,
  `category`, `description`, `keywords`. Single source of truth for all
  metadata (it flows into each page's `<head>`, `<h1>`, meta line, the feed,
  and the sitemap).
- `content/posts/<file>` — just the article body: the inner HTML of
  `<article>`, **without** the `<h1>` or the meta line (those are generated).
- `templates/post.html`, `templates/index.html` — the page shells.
- `partials/masthead.html`, `partials/footer.html` — the banner and footer
  shared by every page. Change the header once here; every page picks it up
  on the next build.

Placeholders are `{{name}}`; `build.py` fills them.

## Adding or editing a post

1. Write the body in `content/posts/YYYY-MM-DD-slug.html` (article inner HTML;
   no `<h1>`, no meta line — the build adds those from `posts.json`).
2. Add an entry to `posts.json` (all six keys).
3. Run the build:

```bash
python3 tools/build.py
```

4. Commit **both** the sources and the regenerated output (GitHub Pages
   serves the committed files as-is — there is no build on their end).

To change the masthead or footer sitewide, edit the `partials/` file and
rebuild. To rename a post, rename its content fragment + `posts.json` entry,
rebuild, and leave a redirect stub (a file with
`<meta http-equiv="refresh">`) at the old path so existing links survive.

## Validation

```bash
python3 tools/validate.py
```

Checks `posts.json` is well formed, every entry has the required keys and a
matching content fragment, and no fragment is orphaned.

CI (`.github/workflows/validate-posts.yml`) runs `validate.py`, then rebuilds
and fails if any committed output differs from what the sources produce — so
stale generated files can't ship. Runs on push to `main` and on every PR.

## Conventions

- File naming: `YYYY-MM-DD-slug-title.html`.
- `category` is one broad bucket (`hardware`, `ai-workflow`, `machining`,
  `ai-security`). It shows in the meta line and the feed.
- Styles: `base.css` (reset, body, masthead, footer — every page) +
  `style.css` (landing page) + `posts/post.css` (posts). Referenced fonts:
  `"Roboto Mono"` is used but not yet self-hosted, so it currently falls back
  to the system monospace.
- Local preview: `python3 -m http.server` then open the printed URL.

## Structure

```
posts.json               front matter (edit)
content/posts/*.html     article bodies (edit)
templates/*.html         page shells (edit)
partials/*.html          shared masthead + footer (edit)
tools/build.py           the generator
tools/validate.py        source checks
base.css style.css       styles
posts/post.css
index.html               ── generated ──
posts/*.html             ── generated ──
feed.xml sitemap.xml     ── generated ──
robots.txt               ── generated ──
```
